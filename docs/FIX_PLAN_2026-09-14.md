## 1. 能否一次完成

**可以将已识别缺陷的代码修复、回归测试、双平台构建和文档更新纳入一轮连续实施。** 内部按依赖分成七批，每批通过针对性检查后继续，不需要用户逐文件、逐批批准。

“一次完成”有两个验收层次：

| 层次 | 交付与条件 |
| --- | --- |
| 本地修复候选版 | 完成 F01–F14、U01–U06 及 U07 的明确文案问题，新增正确行为回归用例、通过类型检查和双平台构建；具备现有本地环境即可推进 |
| 可发布验收版 | 在候选版基础上，通过隔离浏览器、真实存储和双设备验收；需要可用的测试 profile、专用存储目标及相应操作授权，不能用模拟测试代替 |

建议按**一个修复任务、分批实现验证、最终统一交付**执行。无需为了修复这些问题重写同步引擎或 UI。实机环境缺失时交付“本地验证通过、实机待验证”的候选版，不标为全部验收完成，也不承诺一次写对或发布后绝无缺陷。

## 3. 必须同时成立的安全约束

1. **范围一致**：比较、哈希、上传、恢复、删除计数使用同一份已规范化范围；范围外节点不移动、不更新、不删除。
2. **失败时停止**：远端状态未知、输入不合法、必要快照未落盘或持锁状态异常时，禁止继续破坏性操作。
3. **成功有依据**：浏览器写入、远端验证和必要本地状态提交均成功后才报告完整成功；部分失败必须显式显示。
4. **一个本地写入口**：所有修改书签、改密、清空及重置操作进入后台共享互斥，不能靠按钮禁用代替互斥。
5. **目标固定**：一次任务固定存储目标、凭据快照、同步范围和本地树版本；执行中切换设置不改变该任务目标。
6. **变更可补偿**：新事件不能被旧上传清除；恢复中断有记录和安全快照；不自动把半恢复状态重新上传。
7. **保留恢复依据**：新备份未验证成功不删除旧文件；不把源码回退当作书签数据或密码状态已经恢复。

### ① 数据与目标边界：F01、F02、F04、F13、F14

**修改范围**：书签范围/规范化/仓储索引，云端数据 helper，文件管理、下载队列、两种 provider，配置与状态键。

- 范围过滤保留根容器，过滤其系统根子节点；兼容确实仍有消费者的平铺输入，但不能用兼容分支替代真实树测试。不得修改调用方持有的原树。
- 全局匹配索引仅包含本轮实际参与恢复的系统根；同 URL 位于排除根时在目标内新建，范围内跨根移动仍复用。未知系统根不自动按任意位置映射到另一个根。
- 下载后先验证结构再计算数量或比较；合法空文件夹与非法无类型节点明确区分。校验标题/URL 类型、根结构、节点数/深度和解压大小，超限报错而非截断恢复；兼容实际历史备份。
- 从合法原始字段重算书签哈希；不把远端提供的 `hash` 当成可信身份。
- 只有已确认不存在的 WebDAV 备份目录/成功列出的空目录代表“可首次上传”；Gist 目标 404 代表目标不可访问，不等于可自动创建空库。认证、503、超时、解压和校验错误原样阻止同步。
- 目标键包括驱动、规范化端点和账号/库标识；缓存、下载去重、同步状态、最近备份、最近设备和待确认信息均关联目标。密码/Token 不进入键或日志；URL 不随意转小写路径或删除有业务含义的参数。
- 老状态缺目标/范围信息时，不猜测归属，不用旧文件路径清理新目标；保留旧记录，要求重新对账。未确认归属的基线不能触发自动覆盖或自动合并后上传。

**验收**：真实根范围测试、范围外节点保护、畸形数据零写入、故障零上传/删除、同 URL 不同账号/同库 ID 不同端点隔离。修复 F01 时同步更新所有哈希与删除比例的调用口径。

### ② 恢复与后台互斥：F05、F06、F07

**修改范围**：书签创建/移动/删除和基础合并、快照服务、锁、后台消息、恢复/清空/重置用例及其 UI 调用。

- 创建、更新、移动失败向上抛出并阻止后续删除；基础 merge 路径也不能吞失败后假报成功。删除失败报告部分完成，不保存成功基线。
- 覆盖恢复必须先成功保存当前树安全快照，并保留快照 ID；清理旧快照不能淘汰尚未解除的恢复保护记录。
- 复用后台消息入口，新增本地快照恢复、清空和出厂重置的受控操作。页面发送快照 ID，由后台读取/校验；页面不直接修改书签。
- 将同实例获取锁的判定与占用收拢到一个无异步竞态的入口；现有持久化锁用于跨唤醒状态核对，不把“写入后延迟重读”当作原子互斥。嵌套策略明确继承锁，禁止重复获取或误释放。
- 活跃操作不能仅因经过五分钟就被新操作抢占；记录操作 ID/阶段并核对活跃状态。后台异常结束后将未完成恢复标为“需要恢复处理”，阻止自动上传半成品。
- 清空本地时抑制恢复/删除事件回传，完成后明确显示本地为空和后续同步需确认；重置时先占用后台互斥、停用调度，再清理对应状态，最后释放互斥。
- 错误时不自动反向回滚书签树：保留已完成范围、快照和错误，提供用户确认后的恢复入口，避免覆盖期间真实用户编辑。

**验收**：逐类 API 故障、快照失败、两窗口同时请求、重复点击、操作超时/后台中断、清空与同步冲突；失败无成功基线，无自动上传半恢复数据。真实关闭 popup 的持续执行在第⑦批验证。

### ③ Gist 版本与保留：F03，依赖①②

**推荐方案**：为 Gist 增加一个小型、带版本的 MarkSync 索引文件，记录当前备份引用与已知备份顺序；同步基线使用已识别的远端修订/内容引用，不再把整个 Gist 的时间当作每个文件的时间。具体格式只服务此问题，不扩展为通用版本框架。

- 新文件使用不会因同秒或并发而碰撞的标识；Gist 适配器通过已有 PATCH 能力提交备份和索引变更，写后读取并核对备份内容及当前引用。
- 在现有存储契约中补充必要的备份引用/修订信息，让策略面向接口；Gist 格式细节留在适配器，不在业务层遍布驱动判断。
- **旧 Gist**：单一有效备份可作为迁移候选；多个旧备份若无法从可信历史确认顺序，先展示列表让用户选择。文件名中的设备本地时间只能辅助展示，不能据此静默覆盖或清理。
- 迁移不批量重写、删除旧备份；旧未知顺序文件保留。索引缺项、损坏、指向不存在文件或服务响应被截断时，停止自动写入/清理并提供诊断。
- 多设备同时写入时不宣称具备分布式事务：写前读取、写后核对，检测分叉/未登记的新文件时保留备份并转冲突处理。无法证明当前引用和顺序时停止清理，不依据本次读取的旧列表删除别的设备新文件。
- 清理只针对能证明由本系统管理、顺序已知且满足保留策略的备份；保护当前引用、此次新文件、待处理操作引用。旧客户端和新索引混用无法安全对账时明确暂停自动同步，提示升级相关设备。

GitHub 文档支持一次 PATCH 描述多个文件变更、保留未提及文件，以及读取指定修订；它不构成本方案“具备跨客户端比较交换事务”的证据。以上并发保守处理是本项目设计选择。[GitHub Gist API](https://docs.github.com/en/rest/gists/gists#update-a-gist)

**验收**：随机文件枚举顺序、同时间、多修订、当前文件保护、旧备份迁移、索引损坏、未知文件/截断、两写入者交错执行及写后响应丢失。保留文件而暂停清理是显式降级，不能假报已经完成配额清理。

### ④ 基线与可靠补同步：F10、F11，依赖①②③

**修改范围**：push/pull/smart-sync、状态管理、bookmark-monitor、scheduler、sync-executor。

- 一次上传只取一份本地树；范围过滤、快照、内容比较、上传数据和最终哈希均派生自该版本，移除备份构建内部的第二次读取。
- `skip_identical` 同样提交当前内容哈希、范围标识和远端引用；状态持久化失败不对用户声称完整成功。
- 存储轻量本地变更代数或等价版本标记。任务记录所处理的代数；上传成功只能清除对应代数，期间有新事件则补跑一次。
- 离线、锁占用和恢复冷却时保留待处理状态，用现有 alarm 做有界重试；每次后台唤醒核对，自动同步关闭时保留记录但不执行。
- 恢复写入产生的内部事件不当作用户上传任务；冷却期结束重新比较当前树与恢复后基线，确保冷却期内用户实际编辑能被发现。
- 配置或范围改变后重新建立对应基线，不拿旧全树哈希解释新范围；缺失基线且内容不一致时显式要求选择方向，避免无依据的自动合并回传。

**验收**：重复“已一致”后远端删除正常传播；慢上传中再次编辑必补传；离线编辑后无需再编辑即可补同步；禁用自动同步不被重试绕过；冷却期内真实编辑不丢失。

### ⑤ 加密状态迁移：F08，依赖①②③④

**修改范围**：加密设置 UI、后台受控操作、push 预检/写入设置、云端历史恢复及迁移恢复记录。

- 将“读取旧备份所需密码”和“新备份写入是否加密/使用哪个密码”分开；每次操作固定这两份设置，仍使用现有加密格式。
- 改密/启用/关闭采用明确顺序：占用互斥 → 保存最小迁移记录 → 用旧设置验证远端 → 写入候选备份 → 读回验证 → 确认远端引用 → 原子提交本地新设置与基线 → 标记完成。
- 迁移记录沿用当前 `storage.local` 的凭据存储边界；仅保留恢复迁移必要的旧/新设置和目标文件引用，不写日志或文档，完成后清除临时凭据。
- 对跨网络和本地存储的操作不假设原子性：请求结果未知先核对实际文件；远端已成功而本地设置提交失败时暂停同步，并根据记录恢复提交，不盲目重传或删除候选文件。
- 普通失败保留旧可用设置和旧备份。历史加密备份允许为本次恢复输入原密码，不能要求永久改回全局新密码；关闭加密不意味着历史密文无需密码。
- 多设备需要分别更新密码；检测到其他设备仍使用旧设置时提示冲突/所需密码，不自动覆盖。迁移期间不轮换删除用于恢复的旧备份。

**验收**：旧密文改新密码、启用、关闭再开启、旧版本恢复、错误密码、上传失败、写后读回失败、云端成功但本地保存失败、后台在各阶段中断。不能以“先保存新密码再尝试同步”作为完成路径。

## 6. 切换、回退与停止条件

### 6.1 建议切换顺序

1. 在独立测试 profile 和专用存储目录/Gist 中验证候选构建，先用合成数据，避免个人数据参与测试。
2. 代码与本地状态读取保持迁移能力；遇到无归属旧基线或无法确定顺序的 Gist，显示迁移/方向选择，不静默覆写。
3. 实机验收通过后，再另行授权实际安装切换；涉及同一云端的设备应协调升级。切换时保留本地快照、原云端文件和旧源码/构建。
4. 新协议引用、加密迁移和旧客户端混用必须通过专门场景；不能仅凭单机成功就恢复所有设备自动同步。

### 6.2 回退安排

- **源码**：根据实施前留存副本与本轮差异恢复，仅撤销本任务改动，保留用户后续修改；未经授权不 `git reset`。
- **本地书签**：从有效安全快照执行受控恢复；操作前明确选择，失败现场先保留。源码回退不会自动恢复已写入书签。
- **云端**：候选文件验证失败保留旧版本；写入结果未知先读取核对。新索引故障时暂停自动化，不能删除索引就当作回退成功。
- **密码**：迁移记录驱动恢复到已验证阶段；旧密文必须保留其可用密码恢复途径。不得假设恢复旧代码即可解密新密码备份。
