## 1. 结果与范围

在独立临时 profile 中加载实际 Chrome 扩展构建，验证失败上传跨浏览器重启后自动重试，以及成功上传的持久化结果。浏览器为 Edge 153.0.4234.32；服务为只监听 `127.0.0.1` 的内存 WebDAV 夹具；书签仅为合成测试数据。

准备和最终读取阶段使用 Playwright。中间观测阶段关闭全部 Playwright 连接和扩展页面，直接启动 headless Edge，检查实际浏览器进程命令行不含远程调试参数。此阶段仅从服务端观察请求，不向扩展发送消息、修改书签或手动触发闹钟。

本轮只修改验收脚本和文档，没有修改应用源码、依赖、版本号或生成产物。

## 2. 验收步骤与实测结果

1. 建立同步基线；启用自动同步后编辑合成书签，让服务返回 503，确认存在未确认的 pending 上传。
2. 关闭准备阶段浏览器，再用同一个专用 profile 启动无调试器 Edge，持续保持服务失败。
3. 观测到启动 **45,536 ms** 后的失败 PROPFIND，随后恢复本机服务。
4. 无进一步用户编辑或扩展消息，服务恢复 **45,154 ms** 后收到 PUT，随后收到对应文件的 GET 回读。
5. 留出落盘时间后终止该测试 profile 对应的进程树。重新打开前再次令服务失败，防止检查阶段补传掩盖确认标记丢失。
6. 读取真实 storage 和书签，确认 ACK 等于原 pending ID、基线指向刚上传文件，两个合成书签均保留。

| 验收项 | 结果 | 证据 |
| --- | --- | --- |
| 无调试器重启后自然重试并补传 | 通过 | 观测阶段 7 次 PROPFIND、1 次 PUT、2 次 GET |
| 成功上传后终止进程，确认标记与基线持久化 | 通过 | ACK、上传路径和实际书签断言通过 |
| 测试资源关闭 | 通过 | 浏览器和 HTTP 服务关闭；另行查询未发现本轮测试 profile 的 Edge 进程 |

最终运行于北京时间 19:38，详细结果见 [results.json](validation/2026-09-14-lifecycle/results.json)。计时来自本机服务端，不表示浏览器保证闹钟精确触发。

首次尝试遇到验收脚本误判：Edge 启动器正常退出并将浏览器交给另一个 PID。已修正为按唯一临时 profile 查询实际进程，清理该次测试进程后重新运行通过；这不是应用缺陷。

