# MarkSync 实际使用验收清单

> 适用版本：1.5.2｜真实服务验收按用户决定延后到实际使用中执行。

## 首次使用前

- 使用个人数据前先导出浏览器书签，确认本地快照功能可用。
- 在扩展设置中配置 WebDAV 或 Gist；凭据只填写在扩展或本机配置文件中。
- 先执行连接测试，再执行首次同步。
- 首次同步若提示方向选择，确认云端和本地内容后再选择覆盖或合并。

## 首次同步后

- 检查书签栏、Other 书签及 Firefox 的书签菜单是否符合预期。
- 在第二个浏览器或设备执行一次拉取，确认新增、改名、移动和删除结果。
- 检查同步历史中的操作来源和结果文案。
- 确认本地快照列表中存在同步前快照。

## 需要重点观察的场景

- 服务暂时不可用后，恢复服务并等待自动重试；确认没有重复备份。
- 一台设备有未上传修改、另一台设备产生新版本时，确认界面要求选择方向并保留本地修改。
- 删除书签后检查另一端是否按预期传播删除。
- 修改加密密码或恢复历史备份时，确认旧备份仍可用，当前密码没有被历史恢复覆盖。
- 浏览器或扩展异常退出后，检查恢复提示、同步锁和本地快照，再决定是否执行回滚。

## 发现问题时保留

- 扩展版本、浏览器名称和版本、操作系统。
- 使用的存储类型及脱敏后的服务域名；不要记录密码、Token 或完整 Authorization 头。
- 操作前后的书签数量、所在根目录和具体步骤。
- 同步历史中的时间、操作类型和错误分类。
- `docs/validation/` 中对应脚本的结果 JSON；真实服务配置文件不要复制进仓库。

## 回滚原则

- 出现不确定结果时先停止继续同步，保留当前快照和云端历史文件。
- 出现恢复提示时先使用“恢复操作前快照”，恢复完成后重新选择同步方向。
- 不要手工删除云端历史备份或修改扩展的本地 storage。
- 问题复现后再继续操作；不要用重复点击覆盖现场。

## 现有工具

- 只读服务连接检查：[verify-service.cjs](../scripts/verify-service.cjs)
- 当前交付边界：[DELIVERY_STATUS.md](DELIVERY_STATUS.md)
- 全部历史验收记录见本目录中的 `*_VALIDATION_*.md`。

真实服务、正式 Firefox UI、签名安装和多设备结果需要在实际环境中单独记录，不能把本机夹具结果当作替代证据。
