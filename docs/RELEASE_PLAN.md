# MarkSync 发布准备方案

> 状态：待确定版本与分发渠道；本文不是已发布记录。

## 1. 两步交付

1. 将本轮修复、测试和验收记录提交到本地 Git，保留现有版本 1.5.2。
2. 确定版本号与分发渠道后生成最终产物，核对产物再签名、推送或发布。

建议下一版本为 **1.5.3**，对应本轮缺陷修复。版本唯一维护源为根 `package.json`；本方案尚未修改版本。

## 2. 发布说明草稿

### 修复

- 改善跨浏览器书签范围隔离、同步基线判断及删除传播。
- 为未完成的恢复操作保留安全快照并暂停同步，支持从界面回滚。
- 加固加密迁移中断恢复，避免重复上传或提前切换密码。
- 使用 Gist 版本索引管理备份顺序，遇到异常版本停止同步。
- 修复后台操作、失败补传、手动日志标记和设置保存流程。
- 完善控制台、恢复提示、窄屏布局及键盘交互。

### 验证与边界

463 项单元测试、双平台类型检查及构建通过；隔离 Edge 集成、指定崩溃恢复和 Playwright Firefox 跨浏览器检查通过。真实服务与正式使用环境验收按用户决定延后到使用中进行，未将其标为通过。详情见[当前交付状态](DELIVERY_STATUS.md)。

## 3. 发布执行条件

| 分发方式 | 需要的步骤 |
| --- | --- |
| 本地安装包 | 确定版本后构建并打包 Chrome ZIP；Firefox 正式版安装需要签名 XPI |
| GitHub Release | 核对目标仓库、分支和标签；明确推送与发布范围；现有工作流在 Release 发布时构建并上传产物 |
| 扩展商店 | 确定商店及对应扩展条目，再按其上传流程执行 |

现有 `.github/workflows/release.yml` 无条件运行 Firefox 签名，需要仓库中的 `FIREFOX_WEB_EXT_API_KEY` 和 `FIREFOX_WEB_EXT_API_SECRET`。本轮仅确认工作流定义，尚未核对凭据可用性或远端状态。凭据不进入文档或提交。

## 4. 切换与停止条件

版本改动后重新执行双平台类型检查、构建和产物 manifest 版本核对。打包使用生成产物，不手工修改 dist。只有最终产物、目标及发布说明明确后才执行外部发布。

若类型检查、构建、签名或产物核对失败，停止后续发布，保留本地提交及前一版本产物；外部操作结果不明时先查状态，不重复上传。真实环境验收按既定决定延后，不因此重新阻塞本地交付。
