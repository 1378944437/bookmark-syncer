## 1. 目标与隔离范围

使用实际 Chrome 构建、独立临时 Edge profile 和仅监听 `127.0.0.1` 的内存 WebDAV 服务。创建合成书签并启用旧测试密码，正常关闭、重新打开 profile，确认初始书签已持久化后再迁移到新测试密码。在服务端保存候选文件后暂停 PUT 响应，通过 CDP `Browser.crash` 终止整个测试浏览器，随后重新加载同一 profile。

验收目标是：旧加密设置和已确认基线不提前改变；迁移意图及候选路径保留；崩溃锁未到期时拒绝并发操作；锁自然到期后校验云端候选；通过校验后提交原迁移意图，不重复上传、不删除旧备份。

使用真实浏览器 storage、runtime 和书签 API；没有替换应用 provider 或修改应用构建。没有访问个人浏览器 profile、真实 WebDAV/Gist 账号或生产书签。

## 2. 场景与结果

| 场景 | 核对内容 | 状态 |
| --- | --- | --- |
| PUT 已提交、响应前浏览器崩溃 | 重启后仍使用旧密码和旧基线；迁移记录逐项相同；原加密锁保留，立即重试被拒绝 | 通过 |
| 候选文件损坏 | 自然等待 300 秒锁超时后修改夹具中的候选内容；恢复必须校验失败，旧密码和迁移记录保留，PUT 次数不增加 | 通过 |
| 恢复原候选并继续迁移 | 普通上传因迁移未完成而被拒绝；继续操作提交持久化的新密码，即使传入不同表单值也不覆盖原意图；无重复 PUT，旧备份和书签保留 | 通过 |

锁等待依据实际持久化的 `sync_lock.timestamp + 300000`，没有修改时间戳、伪造时钟或提前删除锁。此规则意味着崩溃后用户可能需要等待最多约 5 分钟才能继续。
